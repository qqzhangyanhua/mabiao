# 推送到远程服务、按人复盘

码表的立身前提是「本机离线扫描本地文件」。已有的两条联网通道（ADR 0006 Cursor 账号用量、ADR 0008 / 0012 官方额度）都只**拉**数据，从不把本机数据往外送；CONTEXT 里对话记录一条还写着「不要把正文上传」。现在团队要把每个人的对话记录与消耗集中到一处，按人分析、复盘与管理，单机工具做不到。

**决定**：新增「推送 (Push)」——用户在对话记录页手动发起、按时间区间把对话记录（含正文与上下文清单原文）和消耗记录单向送到同仓库的「远程服务 (Remote Server)」，按「远程账号 (Remote Account)」归属存进 PostgreSQL。管理员能看全体成员的数据，含正文。

这是码表**第一条也是唯一一条出站数据通道**，边界写死：

- **仅此一处**：除推送外，任何路径都不把对话正文、注入原文、消耗记录送出本机。备份照旧不带正文（ADR 0011 / 0014）。
- **用户发起**：默认只有手动推送。设置里有可选的每日自动推送（推前一天），**默认关**，开关在成员自己手里，不复用本机摄取定时器（对齐 ADR 0006 的独立开关）。
- **单向**：桌面端不从远程服务读回任何数据参与本机统计；远程服务不是来源 (Source)，不是摄取缓存。
- **不推**：Cursor 账号用量（全设备云端数据，多台机器各推一份会重复）、官方额度、代码量、全局指令。

## 推什么

时间区间 + 可选来源筛选，决定两样东西：

- **对话记录**：与区间**有重叠**的会话**整场**推送，不切开。带目录元数据、全部语义事件正文、上下文清单。ADR 0025 外置在源文件里的正文推送时按位置读回并校验 `text_hash`；任何一条读不回或对不上，**整场跳过**并写明原因，不推半截正文。本机已归档（ADR 0004）的会话照推，正文读不回的同上处理。码表自己生成的会话（ADR 0021「码表生成」标记）照推，标记一并带上。
- **上下文清单**：
  - `injected` 层（Cursor `store.db` 首轮 user 消息、Grok `prompt_context.json` 的 `content`）在推送时**现场从源快照读原文**直接发出，本机仍不落库，不改变 CONTEXT「注入正文不落库」。
  - `on_disk_possible` 层只推条目、路径与体积，**不推文件内容**：现在磁盘上的内容不是会话当时的内容。
  - 源快照已被清理（Cursor 约 40 天）时只推缓存度量，标「来自缓存，无原文」，不得装成现场快照。
- **消耗记录**：`occurred_at` 落在区间内的条目，带推送当时本机按 `cost.rs` 算出的**费用快照**与**定价来源**（来源自带 / 精确匹配 / 兜底 / 未定价）。
- **项目归并线索**：`project` 是本机工作目录，同一仓库在不同人机器上路径不同。推送时只读该目录 `.git/config` 取 remote URL（读不到留空）一并带上。

## 脱敏

管理员可见全部正文，而工具结果里常有密钥。推送前按**内置规则**对正文与注入原文打码常见密钥格式（`sk-…`、`ghp_…`、AWS key、`Bearer …`、`password=` 等），预览里显示打码处数。绝对路径、项目名不打码——复盘需要它们。首版不开放自定义正则。

## 身份、凭证、幂等

- 设置页填 `base_url`、账号、密码。**强制 https**，`localhost` / 回环地址例外。密码只用来换取登录 token（有效期 30 天），**密码不落盘**；token 单独存一份 0600 文件，**不进备份**（对齐 ADR 0012）。过期后在设置页提示重新登录。不用钥匙串（ADR 0006 已移除 `keyring`）。
- 每台桌面端首次登录生成**设备 ID** 与可改的设备名，随推送带上。
- 对话记录按（远程账号, 设备, 来源, session_id）**整场覆盖**：会话后来又长了，再推一次即替换。
- 消耗记录本机只有自增 id，没有稳定主键。由客户端按（来源, 源文件, 时间, 模型, 各口径 token）算**指纹**，服务端按指纹去重。
- 本机删除或归档**不会**触发远端删除。

## 推送流程

点推送先出**预览**：会话数、事件数、消耗记录数、预计大小、打码处数，以及一句「管理员可查看你推送的全部正文」，确认后才发。**按会话分批**，每场会话一个请求，失败的单独列出可重试。本机记推送历史（时间、区间、成功 / 失败数）。

## 远程服务

- Rust（axum + sqlx）+ PostgreSQL。事件放 `JSONB`：各来源事件字段不一，但账号、设备、会话、消耗之间是明确的关系，要按账号隔离、按会话 upsert、按指纹去重，关系库更稳。
- **一个部署 = 一个团队**。两档角色：**管理员**（看全员、管账号、可删任何数据、维护团队价目）与**成员**（只看、只删自己推的）。第一个管理员由服务端命令行创建，之后管理员在网页上建成员。**没有注册接口**。
- **只读网页**（React + Vite + Tailwind）：团队总览（按天 token / 费用趋势，按人、来源、模型、项目拆）、成员页、会话详情（正文、工具调用、上下文清单、本场消耗）、项目页（谁在这个项目上花了多少），可导出 CSV。行为指标（失败率、工具分布）留到下一版。管理员页显示每个成员的「最后推送时间」与「已覆盖到哪天」，缺口一眼可见。
- **统一价目**：每人本机价目不同，同样的 token 会算出不同的钱，按人对比不公平。服务端用团队价目按同一优先级重算（来源自带 `native_cost` > 团队价目精确匹配 > model 兜底 / LiteLLM 快照 > 未定价），跨人对比用统一价；客户端快照保留，供对照。
- **项目归并**：优先按 git remote 归并成同一项目，无 remote 按目录名兜底；管理员可在网页上手动合并、改名。
- 首版**不自动删除**任何数据，不设保留期。

## 代码布局

- `server/`：独立 Cargo 项目，不并进 `src-tauri` crate；`server/web/` 放管理网页；迁移用 `sqlx migrate`。
- `crates/push-protocol/`：推送请求 / 响应的线上格式，桌面端与服务端共同依赖。CONTEXT 与 ADR 0017「`domain` 是唯一数据模型来源」管的是桌面端内部；协议 crate 是**传输格式**，由桌面端把 `domain` 转换过去，不是平行模型。
- 计价优先级抽成共享 crate，桌面端 `cost.rs` 与服务端统一价目同用一份，避免两边漂移。
- `deploy/docker-compose.yml`：服务端 + PostgreSQL 一键起。
- CI 新增服务端 job（fmt、clippy、测试，测试连 docker 起的 PostgreSQL）。

## 考虑过、没选

- **MongoDB**：一会话一文档写起来顺，但账号隔离、跨会话按人 / 项目 / 模型聚合、指纹去重都是关系查询，放弃。
- **桌面端加「团队」视图、从远程拉数据**：打破「远程不回流本机统计」的边界，管理员也不一定装了码表。
- **Metabase / Grafana 直连库**：看汇总数字可以，看对话正文与上下文清单基本不能用。
- **本机存密码自动登录**：凭证扩散面大；token 过期重登一次的代价可以接受。
- **按事件切会话**：远端拼不回完整会话，重复推送也对不齐。
- **只用各人本机费用快照比较**：口径不一，按人排费用不公平。

## Consequences

- 对话正文、密钥（未被规则命中的）、内网地址、客户代码会离开本机，落到管理员可见的库里。脱敏只是兜底，预览里那句提示是给成员的知情告知。
- CONTEXT「对话记录」的「不上传」改为「仅在显式推送时离开本机」；新增「推送」「远程服务」「远程账号」词条。
- 外置正文（ADR 0025）的源文件一旦消失，那些会话就再也推不全，只能跳过。想留住就得在源文件还在时推。
- Cursor 注入原文只在快照保留期内可推；过期后远端只有度量。
- `cost.rs` 的计价优先级从此有三处必须一致：`aggregate.rs`、`query.rs` 与服务端统一价目。抽成共享 crate 是为了让第三处不能悄悄漂移。
- 推送读 `.git/config` 是只读访问，不写用户文件，ADR 0010 不受影响。
- 仓库从单一 Tauri 应用变成「桌面端 + 服务端 + 共享 crate」，`AGENTS.md` 的每次改代码清单与 `docs/agent-layers.md` 的层清单要补「推送」与「远程服务」两层。
