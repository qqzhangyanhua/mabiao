# 工作纪要：本机 CLI 生成的区间总结

用户想知道的不只是「这周烧了多少 token」，还有「这周我到底干了什么」。前者报告已经答了；后者答不了——报告只读消耗记录，而消耗记录按定义不含会话正文。要回答后者只能读对话正文，而正文没有规则引擎能总结，只能交给模型。

这件事有三条几乎必然会来的破例。第一，图省事把它做成报告的第四个 Tab，于是 ADR 0015「报告只读消耗记录」「洞察规则只在 Rust」两条同时失效，日后没人说得清报告能读什么。第二，为了「更可控」在应用里自建一条 HTTP 模型通路，让用户填 API Key，于是码表从「只读本机文件的统计工具」变成一个持有第三方密钥的客户端。第三，用会写回本机会话目录的引擎生成纪要，那条新会话下一轮被当成「你干了什么」再读一遍，工具开始统计自己。

**决定**：新增一级功能与领域产物「工作纪要 (Work Notes)」。它读区间内的**对话正文**，经**本机已安装的 AI CLI** 逐会话总结再汇总，产出一张伸缩长图。它不是报告，不共用 `ReportDto`，不共用周期类型。模型能力一律外包给本机 CLI，应用自身不持有任何模型密钥、不自建模型 HTTP 通路。

本篇同时修订 ADR 0020「分享对话框只出报告」：可分享卡片名单从一种变成两种（报告海报、纪要海报）。ADR 0018「数字禁止跨卡片合并」对新卡片同样有效——纪要海报上的硬数字只能来自它自己那次查询，不得把报告的槽位搬过来。

## 领域词汇

**工作纪要 (Work Notes)**：一段区间内、基于对话正文、由本机 CLI 总结出的自然语言汇总，形态是一张伸缩长图。不是报告，不是洞察，不是独立数据维度，不写进 `UsageRecord`。

**纪要引擎 (Summary Engine)**：被调用来做总结的那个本机 AI CLI。一个 CLI 一个 profile，声明命令名、非交互调用形态、只读与禁工具开关、是否支持结构化输出、**是否会写回自己的会话目录**。

不要把工作纪要叫成「报告」——那个词已归 ADR 0015 的数字海报。不要把纪要引擎叫成「适配器」——适配器特指把原始格式解析成消耗记录（或对话记录）的模块，方向相反。

## 约束一：与报告口径分离

工作纪要**不读消耗记录**来产出叙事。它的输入是 `conversation_sessions` 与 `conversation_events`。海报上允许叠加不需要模型参与的硬数字（会话数、项目数、活跃天数、区间 token 合计），这些数字必须在同一次查询里取齐，禁止前端拼多次调用。

反向同样成立：报告不得读对话正文，不得展示纪要文本。两张海报各自成图，不互相引用对方的数字。

费用与 token 的口径仍遵循全局规则：代码量、官方额度、Cursor 账号用量不得并进纪要海报的任何数字。

## 约束二：模型能力只经本机 CLI

应用**不实现**任何模型推理的 HTTP 客户端，**不存储**任何模型 API 密钥，**不新增**设置页的 key 输入框。唯一通路是 spawn 本机已安装的 AI CLI，登录态由那个 CLI 自己持有。

这不是「暂时先这样」。码表的立身之本是只读本机 CLI 留下的文件；一旦自持密钥，它就同时是统计工具和模型客户端，备份、加密、泄漏面全部要重做一遍，而收益只是一个总结功能。

spawn 的骨架沿用 `official_quota/codex.rs` 的既有形态：`std::process::Command` + 管道、子线程读 stdout、`recv_timeout` 超时、超时 `kill` + `wait`。不引入 tokio，不引入 `tauri_plugin_shell`。

引擎必须以**只读、禁工具**的方式调用，且工作目录固定在应用数据目录下的专用空目录，不在用户项目里跑。首版四个 profile：

| 引擎 | 非交互形态 | 结构化输出 | 只读 / 禁工具 | 写回会话目录 |
|------|-----------|-----------|--------------|-------------|
| codex | `codex exec`，prompt 走 stdin | `--output-schema` | `-s read-only -a never` | 否，`--ephemeral` |
| claude | `claude -p` | `--json-schema` | `--tools ""` | 否，`--no-session-persistence` |
| grok | `grok -p` | `--json-schema` | `--disallowed-tools` | **是** |
| cursor-agent | `cursor-agent -p` | 无，靠 prompt 约束 | `--mode ask` | **是** |

引擎清单由用户在界面上选，只列 `which` 探测到的。会写回会话目录的必须在界面上标出来。上游 flag 改名不做开机自检（每次启动 spawn 十几个进程太重），改为设置页一个手动「检测」按钮跑 `which` + `--version`；实际调用失败时**把 stderr 原文直接呈现**，不要包装成自拟的友好提示——上游改了 flag 时，原文比任何预设文案都有用。

结构化输出的**宽松解析对所有引擎一视同仁**：先按 schema 解，失败则从输出里抠 ```json 块，再失败重试一次，仍失败降级成纯文本条目。`--json-schema` 不是百分之百可靠，不要只给不支持 schema 的引擎写兜底。

## 约束三：会写回会话目录的引擎必须可识别

grok 与 cursor-agent 生成纪要时会在 `~/.grok/sessions` / `~/.cursor/chats` 留下一条真实会话。接入这类引擎，**必须同期**具备识别机制。

识别按可靠性排序，不靠时间窗猜：

1. **能钉 session id 就钉死**。grok 的 `-s/--session-id` 可为新会话指定 UUID，记下来即可精确匹配。
2. **否则靠专用工作目录**。引擎一律在应用数据目录下的专用空目录里跑，该目录会成为会话记录里的项目路径，是一个绝不会与用户真实项目重合的标识。
3. 每次调用另记 `(引擎, 起止时间)` 留痕，仅供排查，不作为判定依据。

识别之后**只做两件事**：从后续纪要的输入里剔除，以及在对话记录里打上「码表生成」标记。

**不从 token KPI 里扣除。** 那笔 token 是真的烧掉了，额度是真的少了。把它藏起来，码表就在自己的核心数字上撒谎，这比「统计里多了一条会话」严重得多。用户该看见的是「本周有 3% 的消耗来自生成纪要」，不是一个被悄悄修正过的总数。

**不删除、不改写用户的会话文件。** 只读是这个应用的底线，为了自己的功能好看去删用户的数据，是拿立身之本换便利。这条与 ADR 0004「源文件消失时归档而非物理删除」同源。

## 输入构造

按 `conversation_sessions` 现有的 `from` / `to` 交集过滤取会话，然后：

**用户可再勾选**：预览列出合格会话（标题、项目、来源、token），不读正文。生成只 map 勾选的那些；事件也只为勾选的会话加载。请求里不带 `sessions` 仍表示区间内全部合格会话。规模闸门按勾选后的数量判定——151 条也可以只勾 20 条再生成。

**剔除零星会话**：事件数少于 3 条、或 token 低于 1000 的跳过。这些通常是误触或一句话提问，喂进去既是噪音又白花一次调用。剔除数量必须在海报上写出来（「已略过 N 个零星会话」），不许静默丢弃。不进勾选列表。

**单会话压到 4–6k 字符**：标题、项目、首条用户消息（1000 字）、中间用户消息（各 200 字，最多 10 条）、末条助手消息（1000 字）、工具调用名的次数统计（如 `Edit×12, Bash×5`）。用户消息序列是任务怎么演进的，末条助手消息是最后成没成，工具名统计让模型能分辨「真改了代码」和「只是问了几个问题」。

**不碰 deferred 内容**。ADR 0011 里超过 4KB 的工具输出只存 2000 字预览，那部分又长又是噪音，不取，也不为纪要去回源文件补全。

**项目字段只取路径最后一段目录名**，不发绝对路径。用户的会话正文本来就已经在那家云上了（他本来就是用这个 CLI 干活的），再洗一遍正文是自欺；但绝对路径里的用户名是我们**新增**发送的、原本不必发的信息，这部分该省。这与 ADR 0020「最贵一次只显示路径最后一段」同一条口径。

## map-reduce 与缓存

**map**：每个会话一次调用，产出一句话摘要。**reduce**：把所有摘要汇总成结构化 JSON。并发 3 路——串行太慢，更高会撞各家限流。

两张表，不是一张：

- `summary_session_cache`：单会话摘要，键 `(source, session_id, 内容指纹, 引擎, 模型)`。指纹用 `conversation_sessions` 已有的那个，会话续写就自动失效重算。
- `summary_reports`：最终纪要，键 `(区间, 引擎, 模型, 参与会话集合哈希, 补充指令)`。字段按「将来能长出历史纪要列表」设计，列表 UI 本期不做。

两张表是必须的。周期语义是「进行中的本周」，同一周会被反复生成；只做一张表的话每次都是全量重算，这功能会慢到没人用第二次。

## 周期

`kind` 为 `today` | `this_week` | `this_month` | `custom`，语义是**至今**：今天 00:00 到现在、本周一 00:00 到现在、本月 1 号 00:00 到现在、或自定义闭区间。本地时区，与工作时间线同一套日历日。

**不复用 `ReportPeriod`**。那个类型的 `offset = 0` 指最近一个**已结束**的自然周期，进行中的不可寻址（ADR 0020）。两套相反的语义共用一个类型，迟早有人在某个入口拿到错的一周。

自定义区间最长 **31 天**，不是报告的 93 天——报告的 93 天是一句 SQL，这里的 93 天可能是四百次模型调用。

## 规模、成本与中断

会话数超过 **60** 二次确认，超过 **150** 拒绝并提示收窄区间。

**生成前必须给预估**：会话数、预计耗时、预计消耗。输入 token 可由压缩后的字符数推算，费用复用 `cost.rs` 与 `PriceTable`。**生成后展示实际用量**——codex 的 `--json` 与 claude 的 `--output-format json` 都回吐 usage。

一个能跑五分钟、能花掉真钱的操作，没有事前预估就是在替用户做花钱的决定；没有取消按钮就是不让他反悔。两者都必须有。

进度沿用对话索引那套：后台任务把「已完成 / 总数 / 当前会话标题」写进 `AppState`，前端轮询。**不为这一个功能往代码库里塞第二种进度机制**——现有 Tauri event 推送只有托盘弹窗一处，对话索引进度是轮询，跟着后者。

## 输出与海报

reduce 的输出结构焊死：一句话标题、**3 到 6 个条目**（小标题、一句话说明、关联项目）、一句收尾。条目数由模型按内容多少自己定，海报版式必须可伸缩。

条目数不固定是刻意的。固定五条会逼模型在内容少的那一周硬凑，凑出来的都是废话，而废话出现在一张要发出去的图上，伤害比留白大得多。

海报**新做 2–3 种 DOM + CSS 风格，不碰现有 8 种**。现有风格是给报告的七个固定数字槽位设计的，其中 6 种是 canvas 手绘；要让 canvas 承载长度不定的文本条目，等于给六种风格各手写一遍文本测量、断行、溢出与重排。DOM 走 `modern-screenshot` 的 `domToPng`，内容自然撑高，这些浏览器全包了。

沿用报告的既有约束：不 `@import` 主样式表（ADR 0016）、不用 ECharts、不用 html2canvas、导出 2×、只写系统剪贴板不落盘（因而不触发 ADR 0010）。

## prompt

map 与 reduce 的主 prompt **写死在 Rust**，与 ADR 0015「洞察规则只在 Rust」同构。用户可另填一段**补充指令**（如「我是后端，重点讲架构改动」），拼在主 prompt 末尾，并**计入缓存键**——改了不重算，用户会以为自己的话没生效。

不开放主 prompt 编辑。放开会同时打穿结构化输出约束、缓存键、以及「同一份数据两次结果对不上」时的可排查性。

## 测试

Cloud / CI 一台机器上一个 AI CLI 都没有，代码库里也没有 mock server。因此按缝切开：

- **构造命令行参数**与**解析引擎输出**做成不碰进程的纯函数，各引擎真实 stdout 存 `tests/fixtures/` 当样本。这跟官方额度「fixture + 解析函数」是同一套做法，能覆盖绝大部分逻辑。
- 输入构造（会话筛选、零星剔除、单会话压缩）是纯函数，用 fixture 会话测。
- 缓存键、周期解析、规模闸门是纯函数，直接测。
- 真正 spawn 的那层写 `#[ignore]` live 测试，照 `cursor_credentials.rs` 的先例，只在开发者机器上手动跑。
- 海报 DOM 与截图仍不在 CI。

## 明确不做

Markdown 导出与落盘、历史纪要列表 UI、定时自动生成、把代码量或 git commit 并进「产出」、自建模型 HTTP 通路与密钥存储、开机自检 CLI、删除或改写引擎写回的会话文件、正文脱敏开关、把纪要文本画进报告海报、PDF。

git commit 是另一个全新数据源，值得单独一轮讨论，不捆在首版里。代码量只有 Cursor 一家有，14 个来源里覆盖不全，混进「产出」会让这个词在不同用户那里含义完全不同。

## Consequences

- 看到有人把工作纪要塞进 `ReportDto`、或让报告读对话正文，就是在违反本篇与 ADR 0015。
- 看到设置页出现模型 API Key 输入框，就是在违反约束二，不是「多给用户一个选择」。
- 接入任何新的纪要引擎前，先回答「它会不会写回自己的会话目录」；会写就先做识别，不做识别不许接。
- 纪要消耗的 token 照常进 KPI。有人提「把码表自己烧的 token 藏起来让数字好看」，那是让工具在核心数字上撒谎。
- 可分享卡片自本篇起有两种。再加第三种之前，先改本篇与 ADR 0018 的卡片名单。
- 测试缝：引擎命令行构造、引擎输出解析、输入构造、缓存键、周期解析、规模闸门。spawn 与截图不在 CI。
