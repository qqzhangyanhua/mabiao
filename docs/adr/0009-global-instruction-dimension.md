# 全局指令作为独立维度

各 Source 都有跨项目生效的用户手写偏好，但路径、格式、加载约定互不相同。用户要回答的是「我的 AI 现在吃了哪些指令」，不是「硬盘上有哪些 markdown」。这与消耗记录、代码量、Cursor 会话、官方额度都不是同一件事：它不计量用量，也不该进入任何 Token KPI。

**决定**：新增独立维度「全局指令 (Global Instruction)」。打开视图时实时读盘，汇总各 Source 真正会加载的用户手写指令，附带加载状态与体检异常。不写入 sqlite，不进入 `UsageRecord`、`Source` 枚举或本机 token 聚合。界面作为独立顶级项，与统计分区。

这是继 ADR 0006 / 0007 / 0008 之后的又一个显式独立维度。边界如下：

- **不产生消耗记录**：全局指令不是用量条目，不得塞进统一聚合。
- **不进 Token KPI**：总览、趋势、对话记录等统计口径一律不读本维度。
- **界面分区**：侧边栏独立入口，位于「设置」上方，视觉上切开统计区与配置区。
- **不缓存**：指令文件自身即是源。全机相关文件约十个、几十 KB，实时读盘是毫秒级；缓存只会引入陈旧——用户在外部改完切回应用还显示旧内容，恰好摧毁「随时查看」。
- **权威口径**：以「该 Source 真正会加载的」为准，不是「磁盘上存在的文件」。存在但不被加载、本地不可见、未创建，是三种不同状态。
- **机器记忆不进本维度**：Cursor 遗留 memories、Claude 自动记忆是机器写的、按仓库或状态不明的残渣，只可作为体检项展示，不得进入全局指令数据模型。

写入用户文件的约束不在本 ADR。见 ADR 0010。两份拆开是因为生命周期不同：本维度边界写完基本不动；写入约束会被后续每个想写文件的功能反复引用与修订。合在一起，查阅「能不能写文件」的人要读一整篇讲维度的文档。

**理由**：看不见就会忘记维护，失效也是无声的。本应用手里有全部 Source 的消耗记录，能把指令投入与消耗记录交叉，这是它该长在本应用里、而不是做成独立小工具的理由。

## Consequences

- DTO 定义在 `domain` 模块（根文件 `domain.rs` 全量 re-export），与其它独立维度同一出处；前端类型手动同步。
- 每次进入视图重新读盘，没有「最后一次正确结果」可回退——读失败就显示读失败，不得用旧快照冒充当前指令。
- 路径约定会随各 Source 版本演进而过时；证据等级（已验证 / 推测 / 无机制）是缓解，不是消除。
- Cursor 的账号级偏好在服务端，本地不可见；不得为此去写 Cursor 的 sqlite。
