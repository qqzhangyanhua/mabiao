# 自定义额度提供商

> **2026-09-03 修订（实现细节）**：预设枚举现为 7 种（0013 新增 `litellm_proxy`）；已实现档见 `CustomQuotaPreset::implemented()`（OpenAI 兼容 / NewAPI 别名 / LiteLLM Proxy）。托盘「最紧一档」不再按 `custom:` 前缀一刀切，而是按窗口有无 `resets_at` 分流（0013，`official_quota::tightest_window`）。读到下文「跳过全部 `custom:`」「一次性 6 种」时以 0013 为准；边界条款（只打计费接口、不进消耗记录、密钥不进备份）仍以本篇为准。

内置的 9 个官方额度账号之外，用户还在用第三方 API 中转站和聚合服务：OpenAI 兼容中转、自建的 NewAPI / OneAPI 站点、OpenRouter、DeepSeek 等。这些普遍是充值制，比订阅制**更容易毫无预警地断掉**——而「官方额度」区块只认写死的那 9 家，恰好漏掉了最容易断的那条。

**决定**：新增「自定义提供商 (Custom Quota Provider)」——用户在设置页自行登记、按**内置预设类型**取数的账号级额度来源。它属于「官方额度」维度。

## 边界

这是 ADR 0008 之后的又一条受控联网通道，且是第一条**目标地址由用户提供**的通道。因此边界必须写死：

- **只允许内置预设类型**，**明确排除**用户自填 JSON 指针的通用映射。解析器编译进应用，用户只选类型、不填指针。排除有两条理由：其一，地址与映射都交给用户之后，这条通道就不再受控，正是 ADR 0008 禁止的通用摄取——应用等于一个能指向任意接口、按任意路径取值的取数器，「受控通道」四个字名存实亡；其二，报错只能写成「指针 /data/quota 找不到」，用户看不懂，而内置解析器能报「用量接口里没有 total_usage」，用户也不需要读接口文档。
- **只打计费 / 余额接口**。不下发模型调用，不拉取会话，不摄取任何正文。
- **不进消耗记录**、不进 `UsageRecord` / `Source`、不进本机 token KPI、不进 5 小时 / 7 天估计窗、不进 Cursor 账号用量、不进代码量与趋势明细。
- **凭证不进备份**。配置（名称 / 类型 / 地址 / 开关）与密钥分两份文件存；备份目录是设计成给人整个拷走的，密钥进去等于每次备份都在扩散凭证。

## 架构：平行通道

内置 9 家的 `OfficialQuotaProvider` 枚举及其穷尽匹配**一行不改**——它们的编译期穷尽保障不因这个功能被削弱。自定义提供商走一条平行通道，两边各自产出额度行：

- **合流点**：`official_quota::load_dto`，内置行之后追加启用的自定义行。这是整个应用（首页、托盘、告警）取用额度数据的唯一出口。首页和托盘因此零改动；告警去重键本来就是字符串，形状也不用改。给不出重置时间的自定义窗口要在 `prepare_notifications` 里用空重置键放行（见「退避与告警」）。
- **取数**：并入现有的作用域线程池 `fetch_in_parallel`，与内置各家同一波并发，不新增调度机制。两侧共用 `QuotaTarget`（标识 + 展示名）这一个形状。
- **退避与告警**：退避状态的映射键、告警去重键的 provider 字段本来就是字符串，天然兼容，状态文件格式不变、无需迁移。有百分比的自定义窗口走现有的 80% / 100% 告警，复用**同一个**告警总开关；只有金额、算不出百分比的窗口不参与。给不出重置时间的自定义窗口去重键里这一段为空（已知缺陷，见 #81）。
- **托盘最紧一档**：`tightest_window` 对**自定义**提供商按窗口有无 `resets_at` 分流——带重置时间的预算窗可参与标题竞争；充值制余额（无 `resets_at`）仍跳过，免得长期 95% 余额把每天真正在动的 5 小时窗挤掉。内置账号不受这条过滤。

## 标识与命名

标识随机生成、带 `custom:` 前缀（形如 `custom:a3f9c1`）。前缀用于与内置 9 家永不冲突，并在界面上区分自定义与内置。**托盘最紧一档不再按前缀一刀切**（见上节 `resets_at` 分流）。

名称是纯展示标签，可改可重复；**改名不改标识**——额度缓存、退避状态、告警去重记录全部跟着标识走。

## Consequences

- `OfficialQuotaWindow` 增加三个可选金额字段（已用金额、上限金额、币种），允许「只有百分比 / 百分比 + 金额 / 只有金额」三种形态并存。新增字段全是 `Option`，旧缓存不需要迁移（有独立测试盯着这条）。
- 请求地址归一化只在 Rust 存在一份：剥掉结尾斜杠与结尾的 `/v1`，再按预设类型拼接接口路径。前端不重写，否则界面上写的和真正请求的会各自漂移。设置页 base URL 下方那行「将请求」回显走的**就是**取数用的那份请求构造（`request_urls`）——回显存在的唯一目的是「点保存之前就知道填对没有」，另写一份的话它迟早开始骗人。
- **「测试连接」用表单里尚未保存的配置打一次，成功时把解析出的额度窗口原样画出来**，画法与首页共用一份。只回一句「成功」证明不了预设类型选对了，读到的数才能，而共用画法意味着用户此刻确认的就是之后每天看到的那一行。这条通道不写额度缓存、不记退避、也不受既有冷却拦截：配置还没保存，退避里没有它的位置，而用户点测试往往正是为了修好一条正在冷却的。测试失败**不拦保存**——断网、中转站临时抽风、或用户想先把配置填好稍后再验，都不该变成「存不进去」。
- 预设类型枚举一次性定义齐 **7 种**（OpenAI 兼容 / NewAPI-OneAPI 别名 / OpenRouter / DeepSeek / 硅基流动 / Moonshot / LiteLLM Proxy，见 0013）。**已实现档**见 `CustomQuotaPreset::implemented()`：OpenAI 兼容、NewAPI 别名、LiteLLM Proxy；其余在取数入口给出「暂未支持」的人话错误，不 panic。
- 解析接缝按预设类型分派、**只有一个入口**。后续补齐其余预设时接缝数不增长，新解析器直接复用同一个测试入口。
- 恢复备份后配置在、密钥为空。该行显示「未配置密钥，请在设置页重新填写」——这是待办提示，不是取数失败。
- 取数失败沿用「最后一次正确结果」：保留上次窗口，只更新错误文案，且错误必须是人话（密钥失效 / 地址不对 / 网络不通），不是裸的 HTTP 状态码。
- 一个预设里的接口分**必需**与**可选**两级。OpenAI 兼容那套里上限接口是可选的：不少中转站只实现了用量那条，它 404 时降级成「只报已用金额」，而不是让整行取不到数；已用那条是必需的，拿不到就没有任何可显示的东西。
- **保存一条配置会清掉它的退避**。密钥失效会连着失败几次把这一条压进冷却，而用户轮换密钥正是为了修好它；不清的话保存后那次刷新只会回「刚取数失败，N 分钟后自动重试」，把刚做完的修复盖掉。
- 自定义提供商**不进**首页「配置显示」面板。该面板管的是「画不画」，而自定义提供商的开关管的是「取不取数」，语义不同；两处都放会变成两个互相打架的开关。
- 首版 OpenAI 兼容 / NewAPI / LiteLLM Proxy 解析器**照公开接口写、用 fixture 测**，未经真实中转站账号验证。「测试通过」不等于「验证过」。
