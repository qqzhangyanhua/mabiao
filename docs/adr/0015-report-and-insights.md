# 报告与洞察

用户要把一段时间的 AI 用量发出去。现有导出是逐视图的 CSV / JSON / 图表 PNG，拼出来的是仪表盘截图，不是一份能转发的故事。实现周报时，有两条破例几乎必然会来：为了海报好看，把代码量、官方额度或 Cursor 账号用量并进 token 总数；为了改一句话省事，把洞察规则写进 webview。数字错了没法收回，ADR 0002 的「webview 只做展示」也会塌。

现有 ADR 没有一篇把「可分享的周期汇总」和逐视图导出划开。ADR 0010 只管写入用户拥有的文件（含对话 Markdown / JSONL），不管分享海报。本篇把报告钉成派生产物，同时划清它和已有导出的边界。

**决定**：新增领域产物「报告 (Report)」与其构件「洞察 (Insight)」。报告只从消耗记录汇总一个已经结束的完整自然周期，产出一张竖版长图。洞察由 Rust 规则引擎产生，前端只负责措辞与排版。

本期交付称「薄切版」：只做周报、只写剪贴板、七个固定槽位、不依赖上一周期。下文「薄切版」均指这个范围，不是又一个领域词。总览入口与对话框壳子后来由 ADR 0018 收编为「分享」；周报内置视觉风格由 ADR 0019 收编。本篇仍只管报告这一种卡片的口径与槽位。不要因为入口改名或换皮肤就把官方额度写进 `ReportDto`。

这不是又一个独立数据维度。代码量、官方额度、Cursor 账号用量、Cursor 会话、对话记录、全局指令仍然各自独立；报告只读消耗记录，不读它们，也不把自己写进 `UsageRecord`。

## 领域词汇

**报告 (Report)**：某个已结束的完整自然周期内、仅基于消耗记录的可分享汇总，形态是一张竖版长图。它不是 token KPI，不是仪表盘的另一种排版，也不是独立数据维度。

**洞察 (Insight)**：报告里的一条结构化事实，形状是 `{ kind, ...payload }`。payload 只有数值和标识符，不含自然语言。措辞不属于洞察。

不要把报告叫成「摄取报告」——那是 `IngestReport`，摄取诊断，与本词条无关。不要把报告周期叫成「滚动 7 天」——那是本机计费窗。

## 约束一：口径不得合并独立维度

报告的 token 与费用**只**来自消耗记录。

禁止把下列任何一项加进报告的 token 总量、按天序列、来源占比、模型排行、时段占比或最贵会话：

- 代码量（行数，与 token 不是一类量）
- 官方额度（账号级订阅限额，含自定义提供商）
- Cursor 账号用量（云端全设备事件，不进 `UsageRecord`）

薄切版里这三项干脆不出现，不做「独立分区附在后面」。以后若要附，必须另开分区、另标口径，不得并进现有七个槽位的数字。Cursor 会话、对话正文、全局指令同样不进报告数字。

费用优先级与总览相同：`native_cost` > 用户价目 > LiteLLM 快照。周期内没有任何一条能定价时，海报只展示 token，不画 `$0.00`，也不写「暂无费用」。`has_data` 只看消耗记录条数，不看费用。

时间归属用本地时区，与工作时间线同一套日历日，不用 UTC 日切。

一次 `get_report` 返回整份 `ReportDto`。预览里的总量、分日、占比、洞察必须来自这一次调用，禁止前端拼多次查询——中途摄取会让同一张图上的数字互相打架。归一化输出未变，`ADAPTER_VERSION` 不递增。

## 约束二：洞察必须在 Rust 侧产生

洞察规则（选哪个小时、哪一天、哪条会话、占比怎么算）只存在于 Rust `report` 模块。`get_report` command 是它的薄包装。前端 `reportCopy` 把 `ReportInsight` 映射成 `{ headline, comment }`：headline 是中性数字，comment 是第二人称评语。改措辞不必重编 Rust；webview 不算数、不排名、不选槽位。

这条是 ADR 0002「webview 只做展示」在报告上的具体化。把规则放到前端「图省事」，等于让海报数字脱离 `cargo test parity` 和报告入口用例。

新增的时段聚合（按本地一天中的第几个小时 0–23，跨天合并）走 `query.rs`，`aggregate.rs` 必须有内存等价实现。它不是现有 `trend(grain="hour")`（那是时间轴 hour bucket，不跨天合并），也不能复用概览热力图（那是按天的 53 周日历，且在前端算）。

## 周期

`ReportPeriod` 由 `kind`（`week` | `month`）与 `offset`（无符号整数）构成。`offset = 0` 是最近一个已经结束的完整周期，`offset = 1` 再往前一个。当前进行中的周期不可寻址。

周：周一为周首，周一 00:00:00 至下周一 00:00:00（本地，半开）。薄切版界面只暴露周报。`month` 留给后续，模板可以按尺度预留，本期不交付月报。

`has_data = false` 时前端禁用生成，不渲染海报，不出现「暂无数据」或「——」。

## 七个固定槽位

薄切版固定这七个槽位，**全部只依赖当期消耗记录**，不读上一周期、不算环比、不跟历史基线比：

| # | 槽位 | 当期算法 | 海报位置 |
|---|------|----------|----------|
| 1 | 周期总量 | 各 token 口径合计；费用按统一优先级 | 大号数字 + 费用行 |
| 2 | 最活跃时段与深夜占比 | 见下 | 两条第二人称评语 |
| 3 | 最忙的一天 | 本地日历日 token 合计最高；并列取更早的一天 | 统计行 |
| 4 | 来源占比 | 按来源 token 占比，大于 0 的全部画出 | 占比条 |
| 5 | 模型 Top 3 | 按 token 降序最多三条；不足三条有几条列几条 | 统计行 |
| 6 | 最贵的一次会话 | 费用最高的会话；全无定价则改为 token 最多 | 统计行 |
| 7 | 按天柱状 | 该周周一至周日每天 token；零也是 0 高度柱，不是占位符 | 手写 SVG |

不依赖上一周期是刻意的。环比在用户第一次打开时必然算不出来，而第一张图是用户用来判断这功能值不值得继续用的那张。动态槽位、候选池、偏离基线的排序，都不在薄切版。

槽位 2 的两条算法：

- **深夜**：本地小时 0–5（00:00–05:59）的 token。这是「不该还在干活」的窗口，不把晚上 22 点算进去。0% / 100% 文案按**实际 token 是否为零 / 是否等于周期总量**分支，不按四舍五入后的百分比——0.4% 四舍五入成 0 仍是「你 1% 的 token 是在凌晨烧的」，不是「没有烧过」。
- **最活跃时段**：本地 0–23 上长度为 4 的滑动窗口（可跨午夜），取 token 合计最大的一段；并列取起始小时更小的。展示为闭开区间，例如起始 22 显示「22:00 到 02:00」。不在 webview 里再拼窗口。

`ReportDto` 上的当期序列：总量、按天七根柱、来源占比、模型排行。`ReportInsight` 的 kind 只有四条：`night_share`、`peak_hours`、`busiest_day`、`top_session`。payload 不含自然语言。来源用 `Source` 标识，模型用模型名，会话用 `source + session_id`（可附带用量行上已有的项目名）。不读对话正文。

`night_share` payload：`night_tokens`、`total_tokens`、展示用 `pct`（1–99 的整数，仅 `0 < night_tokens < total` 时有意义）。`reportCopy` 先看 token 是否为零 / 是否全量，再决定用哪句；中间那句的数字必须用 payload 的 `pct`，不得自己 round。来源占比的百分比也在 DTO 里已是整数，前端不重算。

`top_session` payload 带 `by: cost | tokens`。全无定价时 `by = tokens`，标签从「最贵的一次」换成「消耗最多的一次」。

### 展示文案（定稿）

kicker 固定「码表 · 周报」。周期行：起止都在同年时为「YYYY年M月D日 – M月D日」，跨年为「YYYY年M月D日 – YYYY年M月D日」。大号数字用现有 `formatCompact`（如 `12.4M`），单位「本周 token」。费用用 `formatUsdAmount`；周期内完全不能定价则**整行省略**，不用 `formatUsd` 的「—」，也不画 `$0.00`。

| 槽位 | 标签 / 标题 | 值 |
|------|-------------|----|
| 1 总量 | 单位「本周 token」 | `formatCompact(total)`；费用见上 |
| 2 深夜 | （评语，无标签） | `night_tokens == 0`：「这个周期没有在凌晨烧过 token。」`night_tokens == total`：「这个周期的 token 全是凌晨烧掉的。」否则：「你 {pct}% 的 token 是在凌晨烧的。」`pct` 四舍五入到整数后夹在 1–99 |
| 2 最活跃 | （评语，无标签） | 「最活跃的时段是 {HH:00} 到 {HH:00}。」 |
| 3 最忙的一天 | 「最忙的一天」 | 周一 … 周日（不写日期） |
| 4 来源占比 | 面板标题「来源占比」 | 图例「{来源名} {n}%」；单一来源就是一条 100% |
| 5 模型 | 一个写「模型」，两个「模型 Top 2」，三个「模型 Top 3」 | 模型名用 ` · ` 连接，有几个写几个 |
| 6 最贵 / 最多 | `by = cost` 写「最贵的一次」，否则「消耗最多的一次」 | 有项目名：`{费用或 token} · {项目名}`；无项目名：只写费用或 token。费用走 `formatUsdAmount`，token 走 `formatCompact` 加 ` token`。不读会话标题，不写「未命名会话」 |
| 7 按天 | 面板标题「按天节奏」 | 柱标签「一 二 三 四 五 六 日」；某天 0 token 画 0 高度柱 |

只有一天有数据：仍画七根柱，六根高度 0；最忙的一天就是那一天；评语不用特写。禁止「暂无数据」「——」「未命名会话」。`has_data = true` 时七个槽位都有当期值（零是值）。

## 渲染路线

海报是**独立的一套 DOM 与受限 CSS**，不是现有界面的快照。截图走 `modern-screenshot` 的 `foreignObject` 路线，由 webview 自己光栅化 CSS。

[#150](https://github.com/qqzhangyanhua/mabiao/issues/150) 的结论是 **GO**。macOS 上 WebKit（与 Tauri WKWebView 同引擎族）和 Chromium 都能把受限 CSS 海报截成与屏上一致的 PNG：中文没有回落到默认字体，字重、字距、布局可用，外圆角走透明通道。仓内说明与复跑见 `docs/spikes/report-poster/NOTES.md`。未在打包后的 Tauri 窗口里再跑一遍；产品接到真实 webview 时用当前主题目视一次即可，不把那次目视当成新的路线选择。

明确不用 `html2canvas`：它自研了一套 CSS 引擎，不认 `color-mix` 和 `backdrop-filter`，而应用主样式表里这两样都在用。

明确不截现有界面：主样式表有六千多行、五百多处 CSS 变量、几十处渐变与阴影，截出来的图与屏幕不一致，且不一致的方式是随机的。

海报里不用 ECharts。需要的可视化只有按天柱状与占比条，手写 SVG / div 百分比即可。这样同时消掉 canvas 在 `foreignObject` 序列化时丢内容的整类问题，也不必为海报另写一套 chart option。

不得 `@import` 或复用应用主样式表。周报内置风格可以使用 `color-mix` 与 `backdrop-filter`（ADR 0019）；额度卡仍按 0018 禁止这两项。隔离门禁由 `src/report/posterCss.test.ts` 盯着。

## 海报尺寸、倍率、水印

- **逻辑宽度 720px**，高度随七个槽位撑开，不固定画布高度。spike 假数据 1× 约为 720×1006。
- **导出倍率 2×**，产出 1440px 宽的 PNG。1× 在视网膜屏上发虚；3×（2160px）对剪贴板过重，分享场景没有收益。用户不可调。
- **薄切版不加半透明水印、不加角标 logo。** kicker「码表 · 周报」是仅有的品牌文字。水印会挡住大号数字，也让转发图看起来像未付费截图。将来若做，必须默认关、不得覆盖大号数字；本 ADR 不预留 DOM 位置。

额度卡仍跟随应用当前主题。周报内置风格各自持有固定色板，见 ADR 0019。截图光栅化无法在 CI 里做像素断言。

## 与现有导出的边界

| 通路 | 产物 | 用途 | 写用户文件 |
|------|------|------|------------|
| 表格 CSV / JSON | 当前视图的行 | 自己分析、再加工 | 原生保存对话框后 `fs::write`，**没走** ADR 0010 唯一入口 |
| 图表 PNG | 单张 ECharts 图 | 当前仪表盘的一张图 | 同上，`export_image` 裸写 |
| 对话 Markdown / JSONL | 单条会话正文 | 备份或外发一份对话 | 走 `user_files::write_export`（ADR 0010） |
| 报告 | 一张叙事海报 | 分享一个完整周期 | 薄切版**只写系统剪贴板**，不落盘 |
| 官方额度卡 | 见 ADR 0018 | 分享一家账号的当前额度 | 只写系统剪贴板；不是报告 |

报告不是「把现有导出拼成一张长图」。表格和图表 PNG 没有叙事、没有洞察、周期口径也不是「上一个完整自然周」。报告不替代它们，它们也不该长出第二人称评语。

薄切版只做剪贴板，因此不触发 ADR 0010。这是有意的：写剪贴板要的是位图，不是用户主目录里的文件。

图表 PNG（以及同一条路上的 CSV / JSON）目前是裸 `fs::write`。这是在 ADR 0010 之前就存在的现状，不是报告的许可。后续处理：

- 报告若补「保存 PNG」，必须先把这条落盘收编进 `user_files` 唯一入口（扩展一次性导出白名单的后缀），禁止再加一处裸写。
- 下一次有人改表格 / 图表的落盘导出，顺手把 `export_csv` / `export_json` / `export_image` 收进同一入口。不在报告薄切版里顺手改——那会把「能不能发出一张图」和「导出入口重构」绑死。

## 明确不做

月报交付、动态槽位、环比、脱敏开关、保存 PNG、把独立维度附在报告后面、第二套主题的验证、定时生成、水印、历史报告留档、PDF。PDF 在分享场景要对方下载打开，转化率低于一张直接铺开的图。

## Consequences

- 实现入口是 Rust `report` 模块的单一函数；前端不得出现第二份时段聚合或洞察规则。
- 测试缝在父 issue #149：报告入口 DTO、时段聚合 parity、`reportCopy` 纯函数。海报 DOM、`foreignObject` 截图、剪贴板写入在 CI 里不测。
- 洞察文案以本 ADR 本节为准；改一句评语只动 `reportCopy`，不动 Rust。
- 看到有人把官方额度百分比画进周报进度条、或把代码量加进 token 总数，就是在违反本 ADR，不是「让海报更完整」。
