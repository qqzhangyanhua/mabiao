# 额度账号存在应用自己的密钥文件里

官方额度原先只读各客户端已经写下的登录态。用户还需要把同一台机器上的多个登录分开看，并且给 Codex、Copilot 一个不改客户端文件的授权入口。

**决定**：额度账号 (Quota Account) 是官方额度维度里可单独开关、可改名的一条登录。标识形如 `acct:<slug>:<hex>`。配置在 `quota_accounts.json`，密钥在 `quota_account_secrets.json`（0600）。密钥不进备份，也不进推送。

来源有三种：

- **导入当前本机登录**：抄一份快照。Antigravity、Droid 的默认路径与零配置取数共用同一条发现顺序（Antigravity 先 macOS 钥匙串再 `state.vscdb`；Droid 先登录钥匙串再 keyfile 再 `auth.json`）。指定了目录的导入和隔离目录只读该目录里的文件，不碰钥匙串。
- **隔离目录**：只登记路径，不把长期密钥复制进应用密钥文件。
- **应用内授权**：只有 Codex PKCE 和 Copilot 设备码。会话只写应用密钥文件。仓库不存放 `client_secret`；Antigravity 的 OAuth 客户端仍在运行时从本机安装里扫描。

客户端文件、钥匙串条目和第三方数据库保持只读。指纹用来去重，也用来判断「这就是当前本机登录」：对上了就读现场凭证，不花已保存的 refresh token。access token 会轮换，有稳定主体或 refresh token 时不用它做指纹。

## 后果

- 恢复备份后配置还在，应用内授权的密钥不在，对应行是待办而不是取数失败。
- 零配置取数的只读边界不变。新增的写入只发生在应用自己的密钥文件。
