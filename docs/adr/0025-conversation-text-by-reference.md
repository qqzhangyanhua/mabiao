# 对话正文按位置引用源文件

ADR 0011 把事件正文写进 `conversation_events`，换来按页读取与正文搜索。代价是对话在本机存了两份：源文件一份，索引一份。真实库（122 万事件、整库 1.9 GB）里事件表 1.1 GB，其中正文 470 MB、`event_id` 180 MB，倒排 440 MB。

**决定**：能从源文件某一行无上下文重建的事件，库里只存它在源文件里的位置与正文指纹，不存正文；读取时按位置回源文件取。

## 哪些事件外置

同时满足才外置：

- 来源的「一行 → 若干事件」映射与上下文无关：**Codex、pi、omp**。本机各抽 1500 条，按行重建的正文与整份解析逐条一致。Claude 只有 83% 一致（跨行合并 `tool_call` / `plan` / `message`），不外置。
- 源文件是明文。Codex `*.jsonl.zst` 的字节偏移指不到明文行，正文留在库里。
- 种类是 `tool_result`、`message`、`plan`。`tool_call`、`system_status`、`error` 留在库里：打开详情时上下文清单与首次使用推断要整场读这几类的正文，外置就是每次打开都回源文件读几千行。
- 摄取时按位置读回该行、重建出的正文与解析结果一致。不一致就照旧存正文，不赌读取时会对上。

外置的行 `text` 为空，`line_offset` 记该行起点的字节偏移，`text_hash` 记正文的 64 位 FNV-1a。本机三个来源外置约 211 MB 正文。

## 读取

分页、单条事件、工作纪要按 `line_offset` 打开源文件、读出那一行、交给该来源的按行重建，再用 `text_hash` 校验。任何一条读不到或对不上——文件被截断、被改写、被删——整页退回整份解析源文件（ADR 0011 的回退路径）；工作纪要退回解析库里登记的会话文件。不拼「部分正文」。

## 正文搜索

倒排改为不存原文的 FTS5（`content=''`、`contentless_delete=1`）。外置行没有正文可供触发器读取，所以倒排由写入方在 Rust 里显式插入，删除触发器按 `rowid` 删。`contentless_delete` 与 `columnsize=0` 互斥，列长度表照存，百万行只多几 MB。

- 会话级命中：外置行不回表 `LIKE` 复核，三元组 AND 召回即算命中。ADR 0014 实测假阳性约 2%，因此总数与排序可能多计少量会话。
- 片段：只对当前页的会话回源文件读候选行、按 `LIKE` 同口径（ASCII 大小写不敏感）复核后切片段；一页内找不到真命中的会话不给片段。

不存原文的表不能 `rebuild`。ADR 0024 第 3 条的全量整理改回 `optimize`，门槛与计数不变。

## `event_id` 不再逐行存可推导部分

`event_id` 绝大多数是 `base64url(源文件路径):行号[:序号]`，路径部分每行重复一份。库里改存：空串表示可由 `file_id` 与 `source_sequence` 推导，`:N` 表示推导值再加序号，其余（原生 ID）照存全文。对外仍是同一个字符串，适配器输出不变，不递增 `CONVERSATION_ADAPTER_VERSION`。按 ID 查单条事件时先解出路径与行号再按 `file_id` 查。

## 迁移

- 新增两列走 `ALTER TABLE`，启动时即刻完成，老库立即兼容写入。
- 后台线程一次性把倒排换成不存原文的形态（从现有正文灌入）、把已有行的 `event_id` 改成推导形态，并把 Codex、pi、omp 的会话标为待补建；随后由既有补建按 `ended_at` 倒序重写这些会话，正文在重写时外置。补建期间这些会话的详情走整份解析回退，搜索仍命中旧正文。
- 倒排换形态之前，写入方照旧存正文、交给旧触发器，不外置。

## Consequences

- **源文件消失或被改坏，外置正文随之消失。** 消耗记录照旧归档（ADR 0004）；摄取失败时上一代索引照旧保留，但这几类事件的正文不再有库内副本，详情只能走整份解析，解析不了就报错。
- 倒排意外丢失时，不存原文的行无法从库内重建；打开库时把涉及的会话标为待补建，由补建回源文件重写。
- 打开一页多一次读盘：同一文件按偏移顺序读，SSD 上为毫秒级。
- 正文搜索的会话总数可能略多于真命中数；片段仍是真命中。
- 备份本来就不带事件表与倒排（ADR 0011、0014），不受影响。
- 本机库副本实测：整库 1938 MB → 1240 MB（123 万事件中 31 万外置，库内正文剩 302 MB；事件表 655 MB、倒排 345 MB）。一次性迁移约 80 秒，补建 2192 个会话约 200 秒；回填正文对翻页耗时无可见影响。剩余大头是倒排与非正文列；再往下要么不建倒排、搜索改扫源文件，要么把会话 ID 等重复字符串字典化，都不在本决定内。
