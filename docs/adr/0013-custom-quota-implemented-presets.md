# 已实现的自定义额度预设：别名、LiteLLM Proxy、按重置时间进托盘

ADR 0012 把自定义提供商立成官方额度的平行通道，并写死了两条实现决定：预设类型一次性定义齐 6 种、托盘「最紧一档」跳过全部 `custom:` 前缀。LiteLLM Proxy 不实现 dashboard billing、枚举里没有位置，预算窗口却带重置时间，把这两条决定都证伪了。同一轮 NewAPI / OneAPI 做成 OpenAI 兼容计费的别名，不涉及这两条。

**本 ADR 不改 ADR 0012 原文。** 0012 的边界仍然有效：只允许内置预设类型、只打计费 / 余额接口、不进消耗记录、凭证不进备份。被取代的只是下面两条实现决定。

**决定**：

1. **预设类型枚举可以再加变体。** 新增 `litellm_proxy`（显示名「LiteLLM Proxy」）。NewAPI / OneAPI 保留为 OpenAI 兼容计费的别名，不删变体、不另打用户接口。
2. **托盘「最紧一档」按窗口有无重置时间分流，不再按 `custom:` 前缀一刀切。** 带重置时间的自定义窗口能参与竞争；没有重置时间的仍跳过。内置账号不受这条过滤。

## 被证伪的两条

**「一次性定义齐 6 种，避免后续补齐时再动枚举」。** 第 7 家确实存在：LiteLLM Proxy 不实现 dashboard billing，枚举里也没有它的位置。新增变体的实际成本（标识、显示名、已实现标记、两处分派）很低，为「以后可能还有」而把枚举焊死，挡的是真需求而不是复杂度。

**「托盘最紧一档跳过所有 `custom:` 前缀」。** 0012 给的理由本身是对的：「最紧」= 最快撞线、撞了会自己重置；充值制余额是存量不是流量，长期 95% 会把标题钉死。错的是按前缀实现这条理由。LiteLLM 的预算窗口带 `budget_reset_at`，正是 0012 自己定义的那种流量型窗口。判据改成「不是自定义提供商，或该窗口有重置时间」之后，LiteLLM 自己的两种 key 会自动分流：设了预算周期的进托盘，永不重置的不进。

## 定义比实现活得久

0012 的两条**决定**被现实证伪，但它的**语义定义**反而被证明是对的。「最紧一档 = 最快撞线、撞了会自己重置」这个定义写得足够准，准到当一个流量型的自定义提供商出现时，能直接指出按前缀实现的判据错在哪。语义定义是对的，错的是按前缀实现的判据。定义比实现活得久。

## 本轮落地

- NewAPI / OneAPI 在请求构造与响应解析两处都指向 OpenAI 兼容计费，接缝数不增长。不删变体是因为配置文件遇到未知枚举值会整份失败，加载再把失败吞成空，用户所有自定义提供商会一起消失。
- LiteLLM Proxy 只打 `GET {base}/key/info`，**不带** `key` 查询参数，普通 virtual key 即可。密钥因此不会出现在设置页「将请求」回显里。响应先读嵌套 `info`，拿不到回落顶层。窗口类型固定为 `budget_window`，托盘短标签「预算」；周期变化只改标签，避免告警去重键跟着用户改预算而变。
- 「不带参数用 virtual key 自查」是从 LiteLLM 源码逻辑推断的，官方文档示例用的都是 master key 加 `key` 参数。实施时未发现调用方式与计划不符，按计划落地。真机若回 403，需要重开：退路是带参数并给回显加掩码。

## 验证状态

NewAPI 那档提出需求的用户手上有真实站点，可做真机验证。LiteLLM 那档没有实例，只能照文档写、用 fixture 测。**「测试通过」不等于「验证过」**——ADR 0012 已经踩过一次这个坑。

## 明确排除

剩下四档不在本轮。OpenRouter 的形状与现有额度窗口兼容，可以单独低成本补上。DeepSeek、硅基流动、Moonshot 三家是纯余额型：余额接口多半只给「还剩多少钱」，没有已用、没有上限。额度窗口的数据模型只有已用金额、上限金额、已用百分比三个位置，没有「剩余」；拿已用去装余额会让进度条画反。这三家会逼出一次数据模型扩展，成本比本轮高一个量级，应当单开一轮并配自己的 ADR。

不为 NewAPI 的额度点数模式做自动探测，不给自定义提供商配置加字段，不打 LiteLLM 的 `/user/info` 或 `/global/spend`。

## 消歧

「LiteLLM Proxy」属于官方额度维度：用户自建网关上那把 key 的预算。「LiteLLM 价目快照」属于费用维度：社区维护的公开模型单价，作为费用推导的兜底层。两者语义无关，用户会在设置页的「额度」页和「费用」页各看到一个 LiteLLM。

## Consequences

- ADR 0012 原文保留。读到「跳过 `custom:` 前缀」「一次性定义齐 6 种」时，以本 ADR 为准。
- `custom:` 前缀仍用于与内置账号永不冲突、以及界面上一眼分辨自定义与内置。它不再是托盘标题的跳过判据。
- 再加一档能取数的预设，只需要动 `implemented()` 与两处分派；「暂未支持」文案从已实现集合推导。
